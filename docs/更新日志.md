### fix · 修复 weave.html 编码被破坏，并把同步桥内联进画布文件
- **事故**：首次集成时用 PowerShell 的 `Get-Content -Raw` + `Set-Content -Encoding UTF8` 往 `weave.html` 注入 `<script src>`，而 PowerShell 5.1 默认按 GBK 读取 UTF-8 文件 → 全文件的**中文注释、字符串全部乱码**，并额外写入 UTF-8 BOM；线上表现为页面把 HTML 当文本渲染、`weave:1116 Uncaught SyntaxError`
- **修复**：从 GitHub 重新下载原版 `APPs/Weave.html`，改用一个 Node 脚本（`fetch` + `Buffer`）注入，全程不经过 PowerShell 文本管线，并加上「无 BOM / 无乱码 / 中文可读」的自检
- ⚠️ **教训（重要）**：处理含中文的第三方文件一律用 Node 的 `readFileSync`/`writeFileSync`（或 Node 脚本）读写，**不要用 PowerShell 的 `Get-Content -Raw` / `Set-Content`**；确需用 PowerShell 时必须显式指定 `-Encoding utf8` 并核对 BOM
- **桥改为内联**：`bridge.js` 以 `<script src>` 外链时会被 Cloudflare 按 URL 缓存，改了内容 URL 不变 → 线上仍拿到旧桥（本次实测命中）。改为构建时把桥内联进 `weave.html`：
  - 新增 `apps/web/scripts/inline-bridge.mjs`：把 `public/weave/bridge.js`（源码，可读可维护）内联进 `weave.html` 的独立 `<script>`，幂等（按内联标记定位替换），并清理可能残留的外链标签
  - `apps/web/package.json` 的 `build` 增加该步骤：`tsc --noEmit && node scripts/inline-bridge.mjs && vite build`；`dev` 仍是外链，改桥即时生效
  - Weave 本体（那一个包含 7500 行的 `<script>`）依旧零改动，桥始终是独立追加的脚本
- 桥的可观测性：新增 `[weave-bridge]` 控制台日志与 6 秒载入超时（失败时把加载遮罩换成可读错误原因），避免再次出现「页面静默卡住、无从判断」
- 画布 iframe 的地址加**构建期版本戳**（`vite.config.ts` 注入 `__CANVAS_VERSION__`），确保 CDN 与浏览器都取到当前构建的画布文件

### fix · 修复关系图关联边被清空的问题
- 现象：给 25 个条目补正文内链后，关系图的 104 条边全部消失，图变成 25 个孤点
- 原因：`PUT /api/entries/:entryId/blocks` 在没有传 `links` 字段时，服务端按「空关联」处理——先 `DELETE FROM entry_links WHERE from_entry_id = ?` 再按入参重建，于是边被清空。补内链的脚本只传了 `blocks`，没传 `links`
- 修复：从每个条目正文块里提取 `entryLink` 标记，据此重建 `links` 并整表重写，边已恢复（25 节点 / 104 边）
- ⚠️ **接口注意**：调用该接口必须始终显式传 `links`（哪怕是 `[]`），否则会静默清掉该条目的全部关联；`entryLink` 标记本身不参与边的写入，只用于服务端从 blocks 重建时兜底
- 附带记录：写入内容用的时间线接口要求「非时间未定事件必须有纪元 + 年份」，负数年份在中文数字风格下会显示为「前XX 年」，可直接用来表达纪元之前的历史

### docs · 地图编辑器方案（第三版：比例尺与尺度系统）
- 新增需求「画图时要让用户知道已画区域有多大，避免造出庞然大物」，落地为**第 7 章比例尺与尺度系统**
- 核心结论：**等距圆柱投影下比例尺随纬度变化**（每 1° 经度实距 = `(πR/180)·cos(lat)`，每 1° 纬度恒定），因此不能放一根固定比例尺条，必须按光标纬度实时换算；由 2:1 白板推出「像素是正方形」，基准量统一为 `k₀ = πR / W`（赤道每像素实距）
- **天体半径是尺度的唯一参数**（`maps.radius_km`，默认地球 6371 km，含火星 / 月球 / 自定义）：半径改变**不影响已画内容**（数据存经纬度），无需重绘与迁移
- 明确两处投影陷阱并给出正确算法：① 屏幕直线≠球面测地线 → 距离用 haversine；② 像素面积随纬度衰减（`k₀²·cos(lat)`）→ 面积必须按纬度带加权，不能用「像素数 × 常数」
- 首期尺度能力：自适应比例尺条、光标实距与变形倍率读数、天体半径设定、笔触与图层面积统计（增量维护，绝不扫全图）、测量工具（折线距离 / 方位角）、真实世界对照（≈1.4 个澳大利亚）、尺度预警（陆地 >15% 非阻断提示）；二期做球面多边形面积与大圆航线
- 新增 §7.9 八项可测验收（含「地球 + 2048 白板：赤道 9.77 km/px、北纬 60° 经度方向 4.89 km/px，误差 <1%」等），并写入「尺度换算错误比没有比例尺更糟」的风险对策
