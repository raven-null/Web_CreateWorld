### perf · 侧边栏切换秒开：路由代码预取 + 页面数据即时渲染
- **目标**（用户要求）：点侧边栏任意按钮切页面都不该出现长加载
- **两个延迟源与对策**：
  1. **页面代码要下载**（懒加载 chunk）→ 新增 `lib/prefetch.ts`：首屏渲染完成后用 `requestIdleCallback` 在空闲时段**预取**常用页面与当前世界内页面的代码；构建产物带内容哈希 + `immutable`，点击时直接读浏览器缓存，不再等网络
  2. **页面数据要等接口** → 新增 `lib/page-cache.ts`（`useCachedResource`）：先把**上次的数据**同步渲染（零等待），再后台拉最新并替换（stale-while-revalidate）；已接入时间线页，其余页面按需推进
- 说明：预取纯属优化，失败静默忽略；不影响首屏（排在空闲时段，且目标都是 2–12KB 的小 chunk）
- 怎么验证的：`pnpm --filter @create-world/web typecheck` 通过；构建产物中预取目标 chunk 齐全

### fix · 构建更新自愈：chunk 加载失败时自动刷新（附一次失败尝试的记录）
- **背景**（用户反馈「刷新后页面加载失败、之前还能打开」）：Cloudflare 的 SPA 回退把**未命中的请求**统一返回 `index.html`（状态码 200）。于是缓存了旧版本前端的浏览器请求**已随新部署消失的懒加载 chunk** 时会拿到 HTML，浏览器按 JS 解析直接报错 → 页面「加载失败」，而且**无法自愈**（普通刷新依旧用旧页面）
- **改动**（前端自愈）：`main.tsx` 监听 `error` 与 `unhandledrejection`，识别 chunk 加载失败类错误（含 `Unexpected token '<'` 这种「把 HTML 当 JS 解析」的典型特征）后**自动刷新一次**；用 `sessionStorage` 标记保证本会话只自动刷一次，避免循环
- **失败尝试（已回滚）**：曾让 Worker 接管 `/assets/*`，按 MIME 判断是否「被回退成 HTML」并改回 404。实测**把真实资源也打成了 404**（JS/CSS 全部失效），立即回滚。结论：不要用 Worker 拦静态资源路径，这里交给前端自愈
- 验证：回滚后真实资源恢复 `200 + text/javascript / text/css`；SPA 深链（`/`、`/w/:id`、`/w/:id/canvas`、`/worlds`、`/login`）全部 `200 + #root`

### fix · 「我的世界」白屏（我加的缓存规则误伤列表接口）
- **现象**：打开「我的世界」页抛 `TypeError: m.map is not a function`，被 ErrorBoundary 捕获
- **根因**：为世界详情加边缘缓存时写了 `/^\/api\/worlds\/[\w-]+$/`，而 **`/api/worlds/mine` 也符合这个形状**（`mine` 同样匹配 `[\w-]+`）——列表接口被当成「世界 id = mine」，走了缓存与权限注入，前端拿到的数据结构被改坏
- **修复**：
  - 新增 `RESERVED_WORLD_SUBPATHS`（mine / new / search）与 `parseWorldIdPath()`，世界详情判定统一走它，保留字一律不当作世界 id
  - 缓存回退路径加**形状兜底**：只有确实含 `id` 与 `name` 的数据才按世界详情返回
- 验证：`/api/worlds/mine` 返回数组（2 个世界、`role=owner`），第二次请求仍是数组；`/api/worlds/:id` 仍为对象且 `canEdit=true / myRole=owner`
- ⚠️ 教训：给 `/x/:id` 这类动态路由加中间件规则时，**必须同时排除同名保留路径**（列表 / 搜索 / 新建），否则会静默改坏相邻接口

### perf · 世界页接口全部走边缘缓存（点卡片进世界不再超时）
- **问题**：点首页卡片进世界页时 `/api/worlds/:id` 超时 8 秒（实测报错），该接口漏了缓存，每次都要吃 Worker 冷启动 + 跨境往返
- **改动**：边缘缓存扩展到 `/api/worlds/:id`、`/api/worlds/:id/entries`、`/api/worlds/:id/graph`，TTL 30 秒
- **方案 A（公共字段缓存 + 权限实时注入）**：世界信息的响应带 `canEdit` / `myRole`（随登录状态变化），不能直接进共享缓存。做法是**写入前剥掉这两个字段**，命中后再按当前访客实时计算补上（查世界 + 查成员，都走索引）
- **关键修复（差点埋雷）**：原先把「缓存中间件」和「权限注入中间件」写成两个，实测**缓存命中时后续中间件根本不执行** → 权限注入从未生效，**登录的创建者被判成只读**（若上到画布就是满屏 401）。改为合并成一个中间件，在内部完成「缓存公共数据 + 实时权限」组装。验证结果：未登录 `canEdit=false/myRole=null`，已登录创建者 `canEdit=true/myRole=owner` ✅
- **实测**：`/api/worlds/:id` **848ms → 226ms**；entries 228ms；graph 242ms；discover 223ms
- 回归检查：缓存后世界信息字段完整（分类 5 个、简介、可见性、标签、ownerName 均在）
- TTL 60s → 30s：编辑后最多 30 秒内可能看到缓存旧内容，窗口更小

### perf · 首屏接口上边缘缓存（1379ms → 213ms）+ 一次死循环事故复盘
- **动机**：用户指出「要用户去关缓存、清缓存本身就是设计失败」——正确。快必须由服务端与前端保证，不能靠用户改设置
- **改动**：`/api/discover` 与 `/api/discover/tags` 是任何人打开首页都要调的公开接口，改用 **Cloudflare Cache API 做边缘缓存（60 秒）**，中间件放在会话解析**之前**（无需认证的请求不再查会话）
- **踩坑 1（缓存永不命中）**：这两个接口原先还挂着应用层的 `cache-control: private, max-age=30`，而 **`private` 会禁止共享缓存写入**——两边配置自相矛盾，边缘缓存永远 `miss`。修法：被边缘缓存接管的路径不再套用私有缓存中间件
- **踩坑 2（首页 307 死循环）**：曾让 Worker 接管 `/` 以便给 HTML 设缓存头（`run_worker_first` 加 `"/"`），结果 assets 返回的 HTML 响应会重定向到 `/`，两者叠加形成 307 循环。**已回滚**：`run_worker_first` 只保留 `/api/*`，首页维持静态直出
  - 补充：该问题只影响「带 query 的首页 URL」与 `/index.html` 直连，裸路径 `/` 始终正常，但仍是必须回滚的错误
- **效果**（线上实测）：`/api/discover` **1379ms → 213ms**（`x-edge-cache: hit`）；`/api/discover/tags` 稳定 216ms；首页 HTML 第二次 209ms
- 已知限制：首页 HTML 的缓存头受 Cloudflare 限制（`_headers` 对 HTML 不生效，实测仍是 `max-age=0, must-revalidate`），刷新时会重新验证一次；不再用 Worker 绕，因为会引发上面的重定向问题
- 怎么验证的：线上连续请求对比耗时与 `x-edge-cache` / `cf-cache-status` 响应头；`pnpm --filter @create-world/server exec tsc --noEmit` 通过

### fix · 画布页不再出现整页滚动条（高度统一成单一变量 + dvh）
- 需求：画布尺寸要「合适」，整页不要形成滚动
- 原因：满屏高度是**多处硬编码 `calc(100vh - 58px)`**（世界区布局、侧边栏、画布内容区各写一份）；顶栏实际高度、浏览器地址栏收放、页面缩放只要差 1~2px，整页就冒出滚动条并把画布推出视口
- 修复：
  - 新增 `--site-header-h: 58px` 作为**唯一来源**，世界区布局、侧边栏、画布内容区全部改成 `calc(100vh - var(--site-header-h))`
  - 用 `@supports (height: 100dvh)` 提供 **dvh 版本**（移动端地址栏收放时 vh 不跟着变、dvh 会，这正是差一截的根源），vh 作为旧浏览器回退
  - 移动端（≤768px）顶栏更高，相应多减 54px，同样带 dvh 版本
  - `CanvasHost` 在画布激活时给 `body` 加 `.canvas-route`（`overflow: hidden`），离开画布即移除——画布是满屏固定工作区，页面级滚动没有用途；这条是兜底，不靠它掩盖布局偏差
  - 画布内容区自身 `overflow: hidden`；画布内部区域（节点列表、节点描述、弹窗清单）的滚动不受影响
- 怎么验证的：线上核对变量使用（世界区 / 侧边栏 / 画布内容区各一处 dvh + 一处 vh 回退）、`.canvas-route` 规则与 `.canvas-page{height:100%;min-height:0}`

### style · 去掉画布页面的滚动条（内容区滚动条保留）
- 需求：画布页面（整体）不要出现滚动条；同时**不要误删**内容区的滚动条
- 定位到的两处「页面级」滚动条来源：
  1. **父页面（React 世界区）**：`.canvas-page` 用的是 `height: calc(100vh - 58px)` 且带 `min-height: 420px`——矮视口下总高度超过可用空间，页面出现滚动条，把画布推出视口
  2. **iframe 内**：顶栏的色点行有 `overflow-x: auto`，颜色多或窗口窄时**行内出现横向滚动条**
- 改动：
  - `.world-content:has(> .canvas-page)` 增加 `height: calc(100vh - 58px)` + `overflow: hidden`（内容区固定高度并裁剪）
  - `.canvas-page` 改为 `height: 100%`、`min-height: 0`（高度由父容器决定，不再撑出页面）
  - 移动端（≤768px）相应改为 `.world-content:has(...)` 的 `calc(100vh - 112px)`
  - 色点行**隐藏自己的滚动条**（`scrollbar-width:none` + `::-webkit-scrollbar{width:0}`），仍然可以横向滚动（滚轮/拖拽胶囊）
- **保留**（未改动，避免误伤）：节点选择弹窗的节点列表、确认弹窗的节点清单、节点描述的滚动——这些是内容区滚动，仍是上一版统一好的细长样式
- 顺带核对：`min-height: 420px` 在别处还有 4 处（条目编辑器、关系图容器、地图页、草稿列表），**都属于其它页面，未改动**
- 怎么验证的：线上核对 iframe 内的隐藏规则与内容区滚动条仍在；父页面构建产物的实际规则（`.world-content:has(>.canvas-page)` 的 height/overflow 与 `.canvas-page` 的 height:100%/min-height:0）

### feat · 从连接点拖出去 → 弹窗选择要连接的节点
- 需求：从节点左右两个连接点拖出去时，弹出选择框挑其他节点，选中即建立关联
- 动机：Weave 原本要求在拖动过程中精确落到另一个节点**很小的连接点**上；节点一多、画布一缩小就点不准（触屏更明显）
- 做法（`bridge.js` 的 `bindSocketDragToPicker` / `openNodePicker`）：
  - 在 `canvasStage` 上用**捕获阶段**监听 `mousedown`，命中 `.socket` 时记下节点与方向（`out` = 右侧输出点，`in` = 左侧输入点），并临时监听 `mousemove`
  - 拖动位移超过 **6px** 判定为「拖出去」，打开节点选择弹窗（轻点连接点不触发，保持原行为）
  - 弹窗列出当前画布上**除自己以外**的全部节点（按标题排序，显示标题 + 摘要），支持**输入关键字过滤**、回车连到第一项；点节点即建立关联
  - 方向映射：右侧输出点 → `本节点 → 目标`；左侧输入点 → `目标 → 本节点`（与 Weave 自己的建线规则一致，箭头方向正确）
  - 建线复用 Weave 的 `App._createConnection`，之后清 `_connOffsCache`、`saveCanvasSnapshot()`、刷新折叠徽标并重画连线，与它自身路径一致；已存在同样的连线时提示「这条关联已经存在」而不是重复建
- 怎么验证的：线上核对拖动监听（捕获阶段）、阈值、方向识别、列表与搜索、`_createConnection` 复用与建线后的刷新调用
- ⚠️ 自测盲区：真实拖拽手势，沙箱内起不了浏览器，**需要人工验证**（从节点右侧圆点往外拖 → 应弹出节点列表 → 点一个节点 → 应出现连线且箭头方向正确；从左侧圆点拖出则方向相反）

### fix · 框选模式对鼠标无效（模式标志没有转成 Shift）
- **现象**（用户反馈）：侧边栏开启「框选」后，拖拽画布空白处无法框选
- **原因**：Weave 的框选分支条件是 `e.shiftKey`（**真实 Shift 键**），而侧边栏「框选」按钮只把 `_boxModeActive` 置为 true。这个标记**仅在触控路径**里被转换成 shift——`_touchBeginDrag` 补发 mousedown 时传 `{ shift: this._boxModeActive }`；**鼠标路径完全没有这层转换**，于是开了模式鼠标拖拽仍然只走平移分支
- **修复**：桥包装 `App.onCanvasMouseDown`，鼠标事件进入原逻辑前补上同样的转换——模式开启时用 `new MouseEvent(...)` 复制一个带 `shiftKey: true` 的事件交回原逻辑（`shiftKey` 是只读属性，不能直接赋值；极端情况下退化为直接改写属性）
  - 与触控路径行为保持一致（框选模式下不能平移画布属于该模式的既有语义）
  - 用 `App._cwBoxModeWrapped` 防止重复包装
  - 顺手给「框选」按钮补了 `title` 说明（开启后拖拽空白处即可框选）
- 顺带：**移除侧边栏的「导出 PNG」按钮**（导出已整合进顶栏的导出菜单，两处重复）；顶栏菜单里的「图片（PNG）」仍调用同一个 `App.exportPNG()`
- 怎么验证的：线上核对包装函数、补 Shift 的条件判断、`MouseEvent` 复制、PNG 按钮移除与顶栏菜单仍可用

### fix · 导出悬浮菜单改成事件委托（原先绑在按钮上，按钮重建后就失效）

### fix · 画布写回 409 版本冲突：并发写同一条目 + 冲突不重试
- **现象**（用户提供的控制台日志）：画布注入 13 节点后又注入 26 节点，随后 `/api/entries/:id/blocks` **刷出一整屏 409**，画布改动实际没保存成功
- **根因两条**：
  1. **并发写**：同一批条目被两次合并同时处理（分类切换/重复注入触发），两个请求携带同一个旧 `version`，服务端对第二个必然返回 409
  2. **冲突不重试**：服务端 409 会返回 `data.latestVersion`，但客户端把 409 当普通失败丢弃——于是每次都失败、每次都重新取详情、下次再冲突，形成刷屏循环
- **改动**（`components/CanvasHost.tsx`）：
  - 新增 `saveEntryBlocks()`：写回遇到 409 就**重新取最新版本再重试一次**，成功后才更新本地版本缓存
  - 同步任务**串行化**（`queueRef` 链式执行）：同一时刻只跑一个合并，杜绝同一条目并发写
  - 分类切换竞态：画布数据记录来源分类（`payloadCategoryRef`），缓存写回用「内容所属分类」而不是「当前分类」；只把数据注入到它所属的分类画布，避免慢请求回来把画布覆盖回旧分类
  - 缓存快照上屏时同步重置出边基线，避免把缓存内容误判成新改动而回写
- 怎么验证的：`pnpm --filter @create-world/web typecheck` 通过；线上入口已含冲突重试逻辑；服务端 409 返回结构确认为 `{ ok:false, data:{ latestVersion } }`

### fix · 页面永远停在「加载中」：API 请求补超时与重试

### fix · 修复关系图关联边被清空的问题

### docs · 地图编辑器方案（第三版：比例尺与尺度系统）
- 新增需求「画图时要让用户知道已画区域有多大，避免造出庞然大物」，落地为**第 7 章比例尺与尺度系统**
- 核心结论：**等距圆柱投影下比例尺随纬度变化**（每 1° 经度实距 = `(πR/180)·cos(lat)`，每 1° 纬度恒定），因此不能放一根固定比例尺条，必须按光标纬度实时换算；由 2:1 白板推出「像素是正方形」，基准量统一为 `k₀ = πR / W`（赤道每像素实距）
- **天体半径是尺度的唯一参数**（`maps.radius_km`，默认地球 6371 km，含火星 / 月球 / 自定义）：半径改变**不影响已画内容**（数据存经纬度），无需重绘与迁移
- 明确两处投影陷阱并给出正确算法：① 屏幕直线≠球面测地线 → 距离用 haversine；② 像素面积随纬度衰减（`k₀²·cos(lat)`）→ 面积必须按纬度带加权，不能用「像素数 × 常数」
- 首期尺度能力：自适应比例尺条、光标实距与变形倍率读数、天体半径设定、笔触与图层面积统计（增量维护，绝不扫全图）、测量工具（折线距离 / 方位角）、真实世界对照（≈1.4 个澳大利亚）、尺度预警（陆地 >15% 非阻断提示）；二期做球面多边形面积与大圆航线
- 新增 §7.9 八项可测验收（含「地球 + 2048 白板：赤道 9.77 km/px、北纬 60° 经度方向 4.89 km/px，误差 <1%」等），并写入「尺度换算错误比没有比例尺更糟」的风险对策
- 全文重新编号：新增比例尺自成一章后，各章顺延为 1~18 章，交叉引用同步校正

### docs · 地图编辑器方案（第二版：球面白板 + 多图层 + 双端一致）
- 需求升级三项并已并入方案：① 白板**长宽有限制**（定尺全球白板，默认 2048×1024，2:1 一套经纬网，可选 1024×512 / 4096×2048 / 8192×4096）② 白板可**转成 3D 地球仪**③ 白板**支持多图层**（政治 / 军事 / 宗教 / 民族…，图层可自由增删）
