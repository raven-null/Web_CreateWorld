## 2. 完成标准（什么叫「做完了」）

**Phase 1 完成的定义**（方案 §16 的三部分验收，全部满足才算）：

| 类别 | 判据 |
|------|------|
| 产品 | 新建白板 → 涂鸦 → 建两个专题图层 → 调顺序 / 透明度 / 显隐 → 放标记关联条目 → 保存 → 刷新一致 → 改尺寸往返无损 → 切 3D 截图 → 导出 PNG |
| 尺度 | 方案 §7.9 的 **12 项**尺度验收全部通过（含 19.55 km/px、北纬 60° 9.77 km/px、面积按纬度带加权等）；已落地为 `packages/map-core` 的单元测试 |
| 显示规则 | 100 个城市符号随缩放正确显隐；`alwaysVisible` 生效；隐藏对象仍可编辑 |
| 3D 美术 | 桌面完整档 ≥50fps；手机默认无大气辉光、可手动开启且刷新后保持；效果单关不影响功能 |
| 插件化 | CI 四硬约束通过；**与本仓库无关的最小宿主**能跑通绘制 / 保存 / 导出；主站页面文件 ≤50 行 |
| 性能 | 改尺寸 2048→4096 ≤3s；32× 放大下涂抹 ≥50fps |

## 3. 里程碑

| 里程碑 | 内容 | 该阶段结束时能做什么 | 大致规模 |
|--------|------|----------------------|----------|
| **M1 地基** | 三个包 + CI 边界检查 + 契约冻结 + `map-core` 纯函数与单测 + 服务端迁移 | 单测全绿；能用脚本创建白板并读写瓦片 | 约 4~6 天 |
| **M2 能画** | 2D 画布（缩放 / 平移 / 经纬网）+ 笔刷 / 橡皮 / 吸管 + 撤销 + 增量保存 + 标记 | **真正能画地图并保存**（第一个能给人看的版本） | 约 5~7 天 |
| **M3 能用** | 图层系统全量 + 比例尺与尺度 + 显示规则 + 白板改尺寸 + 导出 | 能做出世界全图并说清「这块多大」 | 约 6~8 天 |
| **M4 能看** | 3D 地球仪 + 美术三件套 + 性能档位 | 能旋转地球截图分享 | 约 4~6 天 |
| **M5 交付** | 移动端适配 + 最小宿主验证 + 接入文档 + 主站接线 | 可对外说「这是一插件」，其他项目能接 | 约 3~5 天 |

> 规模是**单人全职**口径的粗估，不作为承诺。M2 结束时就有可演示成果，这点很重要——避免长期在「看不见东西」的阶段消耗热情。

## 4. 任务排序与依赖

```
M1 ─┬─ T1 建包 + pnpm workspace 接入
    ├─ T2 CI 四硬约束检查（先立护栏）
    ├─ T3 契约冻结（MapHostAdapter / props / theme / 快照格式 / cwt1 规格）
    ├─ T4 map-core 纯函数 + 单测（投影 / 比例尺 / 单位 / 几何 / 显示规则 / 尺度提示）
    └─ T5 服务端迁移 0007 + 接口实现 + map-core 编解码互测
         │
M2 ─┬────┴─ T6 白板创建 + 地图列表区分 kind + 主站页面接线（几十行）
    ├─ T7 2D 三层 Canvas + 自由缩放 / 平移 + 经纬网 + 瓦片懒加载
    ├─ T8 笔刷引擎（含跨接缝双落点）+ 橡皮 + 吸管 + 地形调色板
    ├─ T9 撤销重做（差异块 30 步）
    ├─ T10 脏瓦片增量保存 + revision 冲突 + 草稿恢复
    └─ T11 标记整合（查看 / 拖动 / 新增 / 编辑 / 删除 / 归属图层）
         │
M3 ─┬────┴─ T12 图层系统全量（增删改排序显隐透明度图例）
    ├─ T13 比例尺与尺度系统（比例尺条 / 实距 / 半径设定 / 面积统计 / 测量 / 预警可调）
    ├─ T14 比例尺显示规则（图层级 + 对象级 + 预设）
    ├─ T15 白板改尺寸（最近邻重采样 + 分批上传 + 无损提示）
    └─ T16 导出（PNG / WebP 降级 + 比例尺与经纬网开关）
         │
M4 ──────┴─ T17 3D 地球仪 + 大气辉光 / 星空 / 昼夜 + 三档性能降级
         │
M5 ──────── T18 移动端适配（触屏手势 / 抽屉 / 档位限制）
         ├─ T19 最小宿主验证（几十行 HTML + 内存适配器）
         └─ T20 接入文档 + 更新日志收尾
```

**关键路径**：`T1 → T3 → T4 → T7 → T8 → T10`（其它任务都可以在关键路径之外并行推进）。

**可以并行的两条支线**（不阻塞 T7 之前的工作）：

- **服务端支线**：T5 可与 T4 同时做（接口一冻结就能写服务端）
- **标记支线**：T11 依赖 T6，可与 T7/T8 并行

## 5. 建议的开工顺序（第一个冲刺）

| 步骤 | 动作 | 完成判据 |
|------|------|----------|
| 1 | 建 `packages/map-core` / `map-editor` / `map-editor-web` 三个包（`private: true`，包名 `@worldmap/*`），接进 pnpm workspace | `pnpm install` 通过，`pnpm -r typecheck` 通过 |
| 2 | 写 CI 边界检查脚本（四硬约束 grep） | 故意在 `map-editor` 里 import 一个主站模块，脚本报错 |
| 3 | 冻结 `adapter.ts` / `types.ts`（`MapHostAdapter`、`MapEditorProps`、`MapEditorTheme`、`MapSnapshot`、`Tile`） | 类型能编译，且**第 6 步的页面接线不需要改动这三个文件** |
| 4 | 写 `projection.ts` + `scale.ts` + `units.ts` + 单测 | §7.9 的 1~6、9~10 项通过（纯函数，不碰 UI） |
| 5 | 服务端迁移 `0007_map_editor.sql` + 四个接口 + `map-core` 编解码互测 | 能用脚本建白板、写瓦片、读回来逐字节一致 |
| 6 | 主站加一条路由 + 一个几十行的页面，用空白画布验证「插件能装进来」 | 打开页面看到空白白板与经纬网 |

**冲刺结束时的状态**：基础设施 + 数据通道 + 空白画布可见。这是 M1 的收尾，也是全项目风险最高的一段（接口设计错了后面会返工），所以放在最前面做。

## 6. 风险与应对

| 风险 | 什么时候会暴露 | 应对 |
|------|----------------|------|
| **接口设计不足**（`MapHostAdapter` 缺方法，做着做着要改） | M2 中途 | 契约先行；改动必须登记更新日志并说明兼容性；`0.x` 允许破坏性变更但要有记录 |
| **Canvas 性能不达 50fps** | T7/T8 | 先做脏瓦片重绘与只绘可见视野；`dpr` 上限 2；仍不行就降低首屏瓦片数 |
| **跨接缝（经度环绕）出错** | T8 | 落笔双写 + 折线断段 + 包围盒双区间三处都要单测覆盖（方案 §8.3） |
| **旧 WebView 缺 `CompressionStream`** | M5 手机验证 | 压缩器注入 + 压缩标识位 + 退化存原始字节（方案 §15.12），**现在就按可注入设计，不要等出错再改** |
| **3D 在低端设备卡顿** | T17 | 三档档位 + 首帧耗时探测；用户手动选择优先，不擅自改回 |
| **范围蔓延**（顺手把标签避让 / 矢量工具也做了） | M2~M3 | 两者已在方案里明确列为二期；M3 结束前不碰 |
| **尺度算错**（比没有比例尺更糟） | T13 | §7.9 十二项验收当单测写，先红后绿 |

## 7. 开工前需要你确认的两件事

1. **是否现在就把 CI 边界检查加进仓库**（`package.json` 的 `typecheck` 或一个独立 `pnpm check:boundaries`）——建议加，越早越省事
2. **第一个冲刺是否按 §5 的六步走** —— 若你希望更快看到画面，可把第 5 步（服务端）暂缓，先用内存适配器做完 T7/T8 的可视验证，再接真后端
