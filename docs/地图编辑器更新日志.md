2. **必须登记的四类事件**

## 2026-10-09 · M3 能用（进行中）

### 工具 · feat · `scripts/draw-world.mjs`：一条命令在白板里画出一张世界地图
- **为什么要有**：手动涂满 2048×1024 的白板不现实，而一张有大陆、山脉、气候带的地图
  是检验编辑器（比例尺 / 图层 / 3D 贴图 / 撤销）最好的素材
- 生成算法（想换一张世界改文件开头的常量即可）：
  - **球面无缝噪声**：经度按圆周采样（cos/sin），白板左右边界天然连续，
    不会在地图正中间露出接缝——这是地图生成最容易踩的坑
  - **大陆场**：若干椭圆核取最大值（重叠自然融合），纬向尺度乘 `cos(lat)` 补偿等距圆柱的拉伸
  - **山脊**：控制点 → Catmull-Rom 样条加密 → 点到线段距离衰减，只在陆地上隆起
  - **气候**：温度按纬度 + 海拔递降；湿度按纬度带（赤道湿润 / 副热带干旱 / 温带湿润）+ 海拔
    → 自然出现沙漠带、温带森林、雪线
  - **河流**：90 条从高地沿最陡下降方向入海（经度环绕、防打转），画成浅海色
- **关键设计：陆地占比由参数决定，不是试出来的**
  原先拿高度原始值与固定阈值比较，换个 seed 陆地占比就从 12% 跳到 40%；
  改成「先算整个高度场 → 按目标占比取分位数定海平面 → 再统一分类」，`--land 0.32` 就是 32% 陆地
- 同理，**深海 / 浅海界线也按分位数**：之前用固定窗口 `seaLevel − 0.075`，
  校准后高度场平缓，导致 43% 的海洋被算成浅海（整片海变成一脸浅色）；
  改成分位数后浅海恒为水域的 8%，也就是贴着海岸的一条浅水带
- 顺带修掉两个自己写出来的 bug：PNG 的 IDAT 误用 gzip 流（应为 zlib，
  而 `deflateSync` 输出的本身就是 zlib，再手动补头会把流破坏）；
  注释与紧随的代码被并到同一行，导致 `for` 循环被注释掉
- 用法：
  `node scripts/draw-world.mjs --world <世界ID> --name "大陆与海洋" [--land 0.32] [--seed N] [--dry-run --out 预览.png]`
- 怎么验证的：`--dry-run` 导出 PNG 逐轮目视核对地形分布
  （海洋 62.6% / 浅海 5.4% / 陆地 32%，森林 12.7% / 山地 8.4% / 雪地 5.1% / 沙漠 3.1%）

### M3 · feat · 纸张改为「整幅拉伸」（用户提问：不能直接拉伸一整张图吗）
- **能，而且对这张图更合适**：羊皮纸是**照片型**素材（一张完整的老纸照片），不是图案型素材。
  平铺适合花纹 / 织物那类可无缝重复的纹理；照片型素材应该整幅铺一次
- 新增 `MapEditorProps.paperFill`（`tile` 平铺 / `stretch` 整幅拉伸），主站用 `stretch`
- 取景规则定案：**取整张，不裁切**。一开始实现的是「按白板比例居中裁切」以避免宽高比变形，
  但羊皮纸是 4:3、白板是 2:1，按比例裁会**丢掉 1/3 画面**——
  纸张是有机纹理，轻微拉伸看不出来，丢画面却看得出来，所以选「整张铺满」
- 分成两个函数把「几何」与「绘制」拆开，几何部分可单测（没有 DOM 也能验证）：
  - `resolveStretchCrop()`：取景规则（整张）
  - `resolvePaperStretchDraw()`：区域换算（世界坐标 → 源图取样矩形 + 目标矩形）
- **踩到的坐标坑（已修）**：`bakeRegionInto` 会把上下文平移到区域左上角，
  此时若还按世界坐标绘制，图案会**整体位移**（撤销一笔后纹理跳一下）。
  现在统一用 `fillPaperRegion(ctx, …, offsetX, offsetY)`：拉伸按世界坐标取源区域、画到目标原点；
  平铺则先把图案相位对齐到**白板原点**，保证局部重烘与整幅烘焙的纹路一致
- 顺带简化：局部重烘不再单独清底（`bakeRegionInto` 内部已铺纸），少一次全区域填色；
  导出图片也用当前纸张（`currentPaperTexture()` → 拉伸模式走同一套铺纸逻辑）
- 素材：拉伸用 `terrain/paper/parchment-full.jpg`（1440×1080，161KB，只做质量压缩不裁不缩）；
  平铺用 `parchment.jpg`（512×512 无缝贴图）保留备用
- 怎么验证的：新增 `packages/map-editor/src/__tests__/paper.test.ts`（7 例）——
  取景规则、整幅铺满的源取样、右下角象限、**局部重烘的目标矩形恒在区域原点**（防位移）、
  白板原点与纸张左上角对齐。`@worldmap/editor` 100 例全绿；`pnpm -r typecheck` 通过

### M3 · fix · 撤销「画面畸形、色块飘到别处」根因修复（历史基线必须冻结）
- **现象**：撤销之后画面错乱，一些色块跑到别的位置；有的笔画撤销不干净
- **原因**（两层叠加，前一轮只修了一半）：
  1. `HistoryStack` 的范围用**真实外接矩形**，而「改动前」的像素按 **256 网格块**存，
     两套坐标原点不一致，拼回来整体平移
  2. 「改动前」的像素是**边画边取**的：快速拖动时某个块第一次被碰到时，
     块内已经含有本次笔画前面落点的内容，取到的不是「开始前」的状态
- **处理**：
  - 范围一律按网格块对齐（`alignToChunk`），`before` / `after` / 写入矩形三者同坐标系
  - 新增 `createHistoryBaseline()`：**指针按下的那一刻**把整幅栅格冻结成基线，
    `record()` 一律从基线裁「改动前」的像素，与落点顺序完全无关
    （2048×1024 拷一份约 1ms，换来撤销结果确定）
- **怎么验证的**：新增 `packages/map-editor/src/__tests__/undo-realism.test.ts`（4 例）——
  真实 2048×1024 白板上两笔分开的色块、跨 256 边界的拖动、连续三笔逐次撤销再逐次重做，
  全部要求**逐字节**与快照一致；`history-flow.test.ts` 追加「已有内容的画布上继续画」与
  「落点跨网格块」两例。`@worldmap/editor` 94 例全绿
- **兼容性**：`HistoryStack.begin(label, baseline)`、`record(layerId, rect)` 签名变更，
  属**插件内部接口**，`@worldmap/core` 对外契约未变

### M3 · fix · 撤销 / 重做只回退笔画的最后一个落点（用户反馈「撤销没用、重做把画面清空」）
- **现象**：画一笔之后点撤销，画面几乎看不出变化；点重做反而像把内容清掉了
- **原因**：`HistoryStack.record()` 每收到一个落点就用新矩形**覆盖**上一条记录，
  而一次拖动会产生几十个落点（`interpolatePointerPath` 补点）——
  最终只保留了最后一个 6×6 的小方块，整条笔画其余部分从未被记录
- **处理**：改成**累加语义**
  - 每个落点把影响矩形并入当前步的外接矩形（`unionRect`）
  - 「改动前」的像素按 **256 网格块**分块快照（同一块只读一次）。
    不按落点分块是因为相邻落点之间有间隙，只存落点会在间隙处留下空洞，撤销时把地形抹掉
  - 结束状态（`after`）在 `commit(reader)` 时按整块矩形统一读取，保存的是笔画真实结果
  - `readRect` / `writeRect` 改为越界安全（网格块会比白板多伸出一截，白板宽高并非都是 256 整数倍）
- **怎么验证的**：新增 `packages/map-editor/src/__tests__/history-flow.test.ts`（6 例）：
  单笔撤销重做逐字节还原、21 个落点的拖动只记一步且矩形覆盖整条笔画、
  三次下笔逐次撤销再逐次重做的字节一致性、擦除多落点撤销后地形完整恢复、空步不入栈、脏矩形累积。
  `@worldmap/editor` 88 例全绿；`pnpm -r typecheck`、`pnpm check:boundaries`（44 文件）通过
- **后续**：这一轮只解决了「只记最后一个落点」，随后的实测又暴露出网格坐标错位与
  「边画边取基线」两个问题，见上方「撤销『画面畸形、色块飘到别处』根因修复」

### M3 · fix · 地图页刷新 / 切图时自动弹出「新建地图」窗口
- **现象**：每次刷新地图页、或点地图标签切换时，新建地图的弹窗会自动冒出来
- **原因**：`MapsPage` 里有一个 `useEffect` 在 `maps.length === 0` 时无条件 `setShowCreate(true)`，
  列表还没加载完（初始为空）就先弹了一次
- **处理**：删掉该自动弹出逻辑，创建窗口只由「+ 新建地图」按钮打开；
  没有地图时保留空状态文案引导（「还没有地图，点『+ 新建地图』开始」）

### M3 · feat · 比例尺与尺度系统（T13）
- 新增 `measure.ts`：测量（折线累计距离、起终点直线距离、初始方位角）与**面积统计**（按纬度带加权：逐行计数后复用内核的面积算法）
- 新增 `export-image.ts`：导出图片——**PNG 优先，超 8MB 自动降级 WebP（质量 0.9）**，两者都超限则抛出可读错误交给宿主提示；导出在离屏画布完成，不影响当前视图
- `MapEditor` 新增六项尺度能力：
  1. **测量工具**：点击折点、实时累计距离与方位角，画布上绘制折线与读数标签
  2. **比例尺条**：按光标纬度实时换算（等距圆柱下比例尺随纬度变化），左下角显示当前刻度
  3. **光标读数**：底部信息条常驻经纬度、每像素实距、横向变形倍率——读数只在数值变化时重渲染，避免指针移动拖慢绘制
  4. **天体半径设定**：地球 / 火星 / 月球预设 + 自定义输入；改半径只影响读数，不动已画内容

### M3 · fix · 面积系数的三次反复（教训：别靠手推，写参照实现）
- 现象：面积统计在「半幅填满」时给出 πR²（应得 2πR²），偏小一半
- 过程：先推断系数从 1 改成 2 → 整幅填满又变成 2 倍 → 改回 1 并**写了一个逐行参照实现**（`宽像素数 × 每像素经向 km × 每像素纬向 km` 按行累加）核对，确认系数就是 **1**：整幅填满精确等于 4πR²、半幅精确等于 2πR²
- 教训：这类「系数差 2」的错误靠心算推导极易来回改错（我改了三次）。正确做法是**写一个能自证的参照实现**，让它与已知恒等式（4πR²）对上，再拿它校准正式实现；同时把「半幅填满 = 半个球面」固化成回归测试
- 附带修正一处测试设计错误：原以为「南北半球各半」能验证纬度衰减，其实两块面积天然相等（cos 的对称性）；改用**纬度跨度相同的两个带**（高纬 vs 低纬）验证，面积比约等于两点 cos 之比

### fix · 撤销 / 重做「点了没反应」：加可见反馈 + 局部重烘
- 用户反馈：点击撤销 / 重做**画面没有变化**。逐段核对链路（按钮 → undo → writeRect → 重绘）逻辑是通的，因此先解决**可观测性**问题：

- 同时修掉一个**确实会让画面不更新**的路径：手绘模式下 `redrawAllRenderBitmaps` 在「缓存不存在」或「拿不到脏区域」时会直接跳过重烘，画面就停在旧内容。现在改为**宁可整幅重烘，也不让画面停在旧内容**

- 教训：撤销这种「操作后有状态、但视觉变化不明显」的功能，**必须给即时反馈**，否则无法区分「按钮没触发」「触发了但没效果」「效果肉眼看不出」三种情况——这是我在此之前无法定位问题的主要原因

### fix · 撤销 / 重做触发 409（并发保存）+ 亮纸配色不可读
- **409 冲突的根因：保存没有互斥锁**。连点撤销 / 重做会各自安排一次自动保存，两个请求带着**同一个 revision** 一起提交，后到的那个必然 409。修复：加 `savingRef` 互斥锁，同一时刻只允许一次保存（`finally` 里释放，避免失败后永久跳过）。这解释了为什么"越急着连点越容易报 409"
- **亮纸配色**：最初把纸张做成亮米色 `#e8dcc0`，结果与深色界面打架——底色亮、界面文字又是浅色，**两边都看不清**。改为**暗纸** `#241f18`：
  - 纸的质感应当来自**纹理与装饰**，而不是靠亮底色
  - 与之协调：画布上的测量读数、比例尺条背景都改为纸张色 + 亮色文字（此前是"深底 + 亮字"，在亮纸上同样看不清）
- 教训：配色是**成组**的（底色 / 文字 / 控件），只改一处必然出问题。我在上一轮只换了纸张底色，没有同步检查画布文字与界面文字的对比度，用户一眼就看了出来

### fix · 滚轮缩放带动页面滚动 / 画布铺满 / 标记加载中断
- **滚轮冲突**：根因是 React 的 `onWheel` 是 **passive 监听器**，浏览器会忽略其中的 `preventDefault()`，于是缩放与页面滚动同时发生。改为原生 `addEventListener("wheel", ..., { passive: false })`，并给画布容器加 `overscroll-behavior: contain`
- **画布铺满**：容器从固定 520px 改为自适应（`calc(100vh - 320px)`，最小 420px）；新增「**全屏**」按钮（`position: fixed` 铺满整页、锁定 body 滚动、Esc 退出）。「适应」按钮也修了——布局刚变化时容器尺寸未稳定会算错，现在下一帧重算一次
- **标记加载中断初始化**：`loadMarkers()` 失败没有 try/catch，异常会**中断整个初始化流程**，导致后面的状态更新不执行——这很可能同时造成「标记不可用」与「撤销按钮不可用」。现在标记失败只提示一句，不影响画地图；加载失败也会明确报错（不再停在「正在加载」）
